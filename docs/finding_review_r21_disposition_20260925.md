## 一、拦路的那条：改名工具会在替换后断言失败（codex 报 + 我实测）

`swap_superseded.py:144` 的断言是**反的**：

```python
body = "\n".join(out)
assert isinstance(body, str) and pat_line.search(body) is not None   # ← 要求「改完还有旧名」
```

它想表达的是「确实改了」，写出来的却是「改完仍含有旧名」。于是
**所有出现处都是 run 类的文件必然断言失败**；而文件是逐个写的，前面的已经落盘 ——
留下**部分改名**，最难查的那种坏法。下一件事正是拿它改 `hz0`/`hz2`。

已改成：剩下的旧名数必须**恰好等于**本文件非 run 类的处数，并加一条行数不变的断言。

## 二、我在临时副本上跑 `--apply` 时撞出来的两条（codex 没看到）

### 1. `\b` 让带目录前缀的写法一处都匹配不到

run 名有两种写法：`foyer_hz0` 与 `pois200_foyer_hz0`。`pois200_` 结尾是 `_`（词字符），
`\bfoyer_hz0` 在那里**不成立**。于是 `gen_backlog.py` / `gen_stall.py` /
`gen_gate_attrib.py` / `compare_rerun.py` **在 dry-run 里根本不出现** ——
改名之后它们会静默留在旧的受污染 run 上，而旧 run 还在镜像里，生成器照样读得到、
照样出数。正是 CLAUDE.md 纪律 3 那类事故，而且是对着「正在重跑的那两条臂」。

改成 `(?<![A-Za-z0-9])` 前缀，右侧 `\b` 保留（防 `_r2_r2`）。改完 dry-run 从 21 处变 31 处。

### 2. 定义处判不全（两条语境规则够不着）

| 处 | 为什么是定义 | 机械替换会变成什么 |
|---|---|---|
| `gen_idle_pooled.py:36` `damaged = {...}` | 「被争用损害的**重跑前**那三条」这个定义本身 | 把干净重跑算进**受损**集合 |
| `compare_rerun.py:18`（docstring 用法示例） | 写的就是「旧 run 新 run」这个对 | `hz0_r2  hz0_r2` —— 自己替代自己 |

两处进 `DEF_LINE` 名单。另加三引号检测，**只提示不自动改判**：把该改的 run 行误判成
定义会让那个文件静默跳过，那个方向比反方向危险得多（codex 的 `run?` 档）。

**自检**：临时副本上 dry-run 31 处（20 run / 1 run? / 其余定义注释），`--apply`
退出码 0、改 16 个文件、残留只剩两处定义。仓库里的文件没动过（`git status` 核过）。

重算 τ₁ 并与 CSV 比对。
