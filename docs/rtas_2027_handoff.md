### 2. 跨模型验证 —— **决定：不做**（codex 裁定，已采纳）

**裁决全文**：`/tmp/codex_rtas/xmodel_out.txt`（**`/tmp` 不持久，已在下面摘录要点**）。

**理由（codex 给的算力证据）**：
- 固定 KV pool `101,432` 下，按官方 config 估算：Qwen3-1.7B 的 KV 约 10.8 GiB、
  4B 约 13.9 GiB、8B 约 13.9 GiB；**8B 再加 ~16 GiB 权重 ⇒ 单卡 24G 不可行**
- **4B 权重 + KV 已约 21–22 GiB，非常紧**，必须实机过 `101,432 ± 20` 守卫
- **稀疏静态扫（4–5 档）算出的 Δ 不能当成「相对完整前沿的 Δ」** ——
  它是探索性的局部插值；**固定 cap 的单点比较或只报 ε 同样回答不了越线问题**
- **trace 可比性的硬限制**：runner 按 trace 的 `prefix_len/input_len` **用各模型 tokenizer
  生成合成 token**、并把模型实际输出带入下一轮 ⇒ **长度计划相同，文本内容与输出行为会变**。
  所以只能说「**固定 token 需求的服务系统对照**」，**不能说「同一批真实文本的忠实重放」**

**结论**：在「8B 放不下 + 4B 勉强 + 判决需要重建前沿」三个条件下，
这个实验产出的会是「1.7B 上一对局部插值的读数」——**既撑不起「跨规模稳健」，又占掉几天 GPU**。

## ⚠ 一条对 AE 有实质影响的发现：**图原来不是字节可复现的**（2026-09-27 19:49）

### 现象

我在收尾复核时发现：**同一份 `make_figs.py` 连跑两次，图 PDF 的 md5 不同**。

### 根因

matplotlib 的 PDF backend **会在文件里写 `/CreationDate (D:2026...)`**
（`strings fig1_frontier.pdf | grep CreationDate` 直接看得到）。
⇒ **渲染像素完全一致，文件字节每次都不同。**

### ⚠ 我为什么会误判：把「像素相同」读成了「字节相同」

r56 中立复核的原话是「三张图与仓库里的**150dpi 渲染像素逐张相同（md5 相同）**」——
它比的是**渲染结果**（正确），**我当时读成了文件字节**，
于是在交接文档里写下「四个生成器全部确定性（重跑逐字节相同）」这类话，
并把 `paper/data/*.csv` 的字节确定性**错误地推广到了图上**。
**CSV 确实是字节确定的；图不是。** 两者被我混为一谈。

### 为什么这件事重要（不只是洁癖）

1. **AE 的硬要求**：`regen_all.sh` 若做「重生成后逐字节对拍」，**图会假失败** ——
   而这会发生在审稿人手里。**这是会砸 artifact 的那一类问题。**
2. 本项目自己的复核流程里已经出现过「图与成品不一致」的判据（C4），
   而**字节不可复现会让那类判据永远处于模糊状态**（到底是不一致，还是只是时间戳）。
3. 它解释了一个我之前没解释的观察：`main.fdb_latexmk` 里记的图 md5
   **每次编译都对不上磁盘**（当时归因于「图是后来重生成的」，其实两个原因都有）。

### 处置

`make_figs.py` 里加 `_META = {"CreationDate": None}`，**8 个 `savefig` 调用全部带上**。
实测：连跑两次，三张图 md5 **完全相同**（`bb82a594…` / `a07c1fe1…` / `397d5bce…`）。

### ⚠ 顺带记一条**同类风险**：`paper/main.pdf` 自己也**不是**字节可复现的

LaTeX 同样会写 `CreationDate`/`/ID`。所以：
- 「成品 PDF 是否与源码一致」**不能**用字节比 —— 要用 `main.fdb_latexmk` 记的
  **输入文件 md5**（这正是 codex r56 第 8 条用的判据，是对的）
- AE 文档里**不许**写「重跑得到逐字节相同的 PDF」
