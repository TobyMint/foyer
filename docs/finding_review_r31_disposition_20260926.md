## 二、新抓到的（全部改了）

### 2.1 唯一性守卫漏掉「斜率单独算」的写法（**已改**）

codex 的构造：`slope = (y1-y0)/(x1-x0); y = y0 + (x-x0)*slope` —— 形状只剩
`(a-b)/(c-d)`，我上一版的 `(a-b)*(c-d)/(e-f)` 正则 match 不到。
而 `slo_sensitivity.py` **当年就是这么写的**（`s0 + (w-w0)/(w1-w0)*(s1-s0)`），
一直没被任何守卫看见。

已改成**两种形状都 match**，白名单扩到四条并逐条写明「为什么不共用是对的」：
`envelope.py`（唯一实现）/ `run_matrix.py`（memfrac 反解）/ `independent_frontier_check.py`
（**刻意独立**）/ `decode_rate.py`（探索脚本，产物不进 `paper/data`）。
`slo_sensitivity.py` 改成 import 共用实现后**输出逐字未变**。

### 2.2 `gen_tierpair` 只核 summary、不核日志（**已改，两层**）

codex 的构造：summary 里保留 `999/0`、把 `steps.jsonl` 截成 **998 行** ——
`one()` 照样返回一组数、`load()` 照样放行。已加第二个来源的守卫
（`x["steps"] != 999` 直接退出），并用**codex 的构造**验证：拒判、不建文件。

**第 32 轮又给了第二个构造**：把 `cap3_fixed` 的 `steps.jsonl` **冒充** `cap3_pd` 的
—— 两条都是 **999 行**，长度守卫放行。已加**身份**守卫：summary 的
`total_duration_ms_sum` 必须等于日志里 `total_duration_ms` 的和
（逐 run 不同：31.27M / 32.20M / 28.33M）。⚠ **`target_output_tokens` 不能当身份判据**

### 2.4 「same-card repeat」与 metadata 不符（**已改**）

`cap3_pd` 在 **GPU 3**，它重复的 `cap3_fixed` 在 **GPU 2**。而 host 侧的
`cap3_hc` 也在 GPU 3。所以它不是「同卡的重复」，**而是「与 host 侧同卡、与原 run 不同卡」**。
已照实写成：与 host 侧配对能去掉「卡」这一半混淆、剩「日期」那一半
（两者仍相隔 3.5 天）—— 这比原措辞**更准确也更诚实**。

### 2.5 「tight to four tokens」的例子来自另一个池子（**已改**）

+4 个 token 那对是**半池**（50,720 丢 / 50,716 池），而原句举的两个例子是**四分之三池**
（76,085 比池高 **11**，75,445 比池低 629）—— **例子证不出那句话**。
已改成先给半池那一对（差 4），再给四分之三池那一对作对照。
