## 一、子 agent（第 14 轮）：我上一版的**因果叙述是错的**

我写的「池子缩小 → 未服务步单调增加」的**梯度**、以及把全池的 0 当对照证据，
被逐条证伪。我**全部复核确认**：

### 1.1 未服务步恰好等于 `prompt_len > 池子`（硬门槛，不是统计关系）

    池子 76,074：超池最小 prompt 76,085（被丢） / 被服务过的最大 75,445
    池子 50,716：超池最小 prompt 50,720（被丢） / 被服务过的最大 50,688

**边界紧到 4 个 token**，6 条 run **0 假阳假阴**。而且**「全池一个都没有」是恒真的**——
trace 最长 prompt 89,436 < 全池 101,432，全池**在构造上**不可能出现。
把它当对照证据是循环论证。

**推论：所谓「梯度」是 trace 的 prompt 长度直方图在三个阈值上的读数**，
不是系统行为。cap2 与 cap3 在同一池子上给出**同一个数** 104。

### 1.2 机制写错了：`evictable_size=0` 解释的是**崩溃**，不是退化响应

两者**可分离**：`cap3_hp` 的退化步从**步 96** 就出现（比崩溃早 661 步）；
`cap3_p75` **999 步、0 报错、0 崩溃，仍有 14 个退化步**。

### 1.3 我的 `unserved_steps` 列是**并集**，自相矛盾

`122 = 72 真退化 + 50 引擎报错行`、`155 = 39 + 116`。报错行是**响亮的失败**
（`failed_steps` 里数得到），与正文强调的「失败计数全程为 0」互斥。
`cap2_hp` 恰好 0 报错行，**掩盖了不一致**。已拆成 `degenerate_steps` / `error_steps`。

### 1.4 分母错、以及两条「独立点」不独立

- 「5.3% of the trace's prompt tokens」的分母是 **prefix 上界**；按 prompt tokens 是 **4.00%**。
- `load50_default` / `load25_budget` 的 `request_id` **完全嵌套在 p75 里**（249/249、125/125）
  —— 是同一批请求的不同截断，**不是独立的第二个家族**。已撤掉那个说法。

### 1.5 OOM 文档里那张表是错的

写「三条超长请求全部服务成功」，实际它们在 index **591/833/843**（我原先写的 123/673/688 也不对），
且全是 `server_prompt_tokens=1` 的退化响应。已订正。

## 二、codex r29：又抓到两条

### 2.1 §III 把两条故障链混成了一条（**已改**）

我写「引擎未执行的步**恰好**是超池 prompt，没有其他步」。**与记录冲突**：
`cap3_hp` 的 **50 个 FAILED 步里有 49 个 prompt 并没超池**（`cap4_hp` 是 114/116）。
那是 OOM 崩溃那条链。

现在写成：**「以成功返回、只带一个 token 的步」** 恰好是超池的那些；
崩溃是**另一条链**，并给出把两者分开的数（49 of 50）。
数据表加了 `error_under_pool` 列。

### 2.2 「引擎报告成功」的归因偏强（**已收窄**）

`status=SUCCESS` 是 **runner 的字段**，不是引擎的。改成
「what comes back is a success carrying a single token（runner 记的）」。

### 2.3 三条检查器假通过（**已修，并用 codex 的构造验证**）

### 2.7 未处置（写明理由）

- **`ck_near` 的关键词换行会产生假 MISS**（codex：把 `stopping at` 合法换成 `stopping\nat` → 4 个假 MISS）。
  这是 `ck_near` 的固有性质（字面 `find`）。**已在 CLAUDE.md 写明「关键词必须同一行内」**，
  且每条检查加完都做过反向测试。**不改成弹性匹配**：那会让「值与关键词在同一段里就行」，
  正是 2.3 那三条假通过的成因。

  这是**实验设计**（池子是靠 memfrac 设的），不是混淆：池子由守卫钉在 50,716 / 76,074，
  metadata 里有 `pool_tokens` 可核。已在 §III 用「pool size」而不是「memfrac」表述。
