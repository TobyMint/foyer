# 预注册：补充重复实验（2026-09-28 写定，**在看到任何新结果之前**）

## 为什么要跑

论文的判决带是 **±1.0 pp**，而现有重复的**自由度只有 1–3**：
`paper/data/replicates.csv` 九组、共 23 条 run，组内 SLO 全距 **0.5–5.11 pp**。
最靠近带的那条（`horizon=2`）两次测到 **−0.30 / +0.22**（都在带内，n=2）；
而 `scans the queue` 三次是 **+1.30 / +2.16 / +0.29** —— **两次越过 +1.0 pp**，
论文已如实披露。**要检验的是「越带稳不稳」，不是以「九条臂均未越带」为预设。**

⚠ **不承诺「噪声会收紧」**：新增 run 可能让全距**变大**。这次补跑买到的是
**把结论与不确定性界定得更可信**，不是「证明负结果」。
即使 18 次全跑完，n=4–6 也未必能分辨 0.3 pp 这样的小差距。

## 纳入与重跑规则（先定死）

1. **保留全部尝试**：成功与失败（崩溃/中止/被争用）的 run 目录都留在 `results/night`，
   不删不改名。新 run 名一律带 `_rep20260928` 标记。
2. **有效 run 的判据**（与既有口径一致）：跑完 999 步且 `failed=0`；
   时间窗口内 `gpu_watch` 无外人（或该 run 无 watcher 记录时按既有惯例披露）。
   **失败/无效的尝试要报出来，不用它们替换。**
3. **失败后的重跑**：允许，但**用新目录名**（`_r2` 递增），**绝不覆盖或搬走既有目录**。
4. **主分析**：每组报**全部有效 run 的 Δ 分布**（min / max / 全距 / 逐条值），
   不是只报均值；**前沿锚点自身的不确定性一并计入**（Δ = SLO_arm − front_slo(wall)，
   而锚点是分段线性插值）。
5. **判决规则不变**：仍用 `frontier.TIE_PP = 1.0` 与 `classify()`（全仓库唯一实现）。
   **±1.0 pp 是判决带，不是统计置信区间** —— 报告里不许把它当 CI 用。
6. **若结果改变判词，就按预定规则如实改**（正负都写），并同步更新摘要 / §I / §V / §VI
   里所有引用该区间的位置（本项目已有「同一主张会用不同的词说好几遍」的教训）。

## 一致性规则（防「新数据被静默忽略」）

⚠ 已查明：`gen_replicates.py` 的 `GROUPS` 是**写死的九组名单**，而 `regen_all.sh` 的
`recover_runs` 是**从交付 CSV 的行序**恢复 run 列表的 ⇒ **新 run 落地后这些生成器会
照样通过、却完全没算新数据**。
⇒ 开跑前必须：(a) 逐张受影响表**显式**更新 run 名单；(b) 修 `regen_all.sh` 里
「先跑依赖 `table1` 的分析、后重建 `table1`」的顺序；(c) 跑完在**实验机**上重生成，
再与本地快照**逐表 diff**。

## 冻结输入的处置

`concurrency.csv` / `gate_attrib.csv` / `projection.csv` 是**旧快照**，它们证明的是
「**旧交付版本**从什么输入得到结果」。新 run 落地后：
1. 先把旧版连同 **sha256** 留档；
2. **逐张判断**新 run 是否应进入它的统计范围（`concurrency` 是车道审计 → 应进入；
   `projection`/`gate_attrib` 的谓词是「跑完的 run」→ 也应进入）；
3. 若应进入，就**生成新版本并标明**，同时给出新的下游结果 —— **不能只在 README 写
   一句「冻结理由不变」就当它代表新分析版本**。

## 运行纪律

- 只用**卡 2/3**；**总并发 ≤ 2 条车道**。
- 每条 run 起跑前确认目标目录**不存在**（存在就拒跑，不搬不删）。
- 链脚本要**核对 lane 里写的 `--gpu` 与它检查的那张卡是同一张**。
- 部署用 `scripts/deploy_to_lab.sh`（原子 rename），部署后**核哈希**。
