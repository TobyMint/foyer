## 一、M2（最重）：阈值敏感性的表**漏掉了头条所依赖的那条臂**，而它**越过了**

§VI 原来写「at a loose one, **one measurement of one of them** does [cross]」，
并给了一张五行表。复核者按论文自己的口径复算：**20s 下越出 ±1.0pp 带的是两条**
（`horizon=1` +1.5、**`horizon=2` +1.02**），而 `horizon=2`（`foyer_hz2_r2`）
**正是 10s 下最近、头条「−0.30pp 打平」所依赖的那条臂**。

**我自己逐位复核确认**（用 `envelope.piecewise` + `table1.csv` 的全精度墙钟）：

```
10s  hz2_r2  wall=270.9757  SLO=87.687688  差 −0.2961   ← 正文的 −0.30 ✓
20s  hz2_r2  wall=270.9757  SLO=95.395395  差 +1.0162   ← 越过
20s  hz1     SLO=94.394394 差 +1.5373
```

**根因**：`slo_sensitivity.py` 算出了全部 29 条臂的 Δ，但**落盘时用的是硬编码的
8 条名单**，而那份名单漏了 `foyer_hz2_r2`（它是「sf0_r2 才是最接近那条」时代的产物）。
**漏掉的方向对论文有利**，所以必须修。

已做：
1. 生成器改成**机械覆盖全部控制器臂**（不再手写子集），`slo_sensitivity.csv` 现在 17 行；
2. §VI 的表补上 `horizon=2` 一行；
3. 正文改成「**two of them do**, each on a single measurement」；
4. **并把两条越线分开说**：`horizon=1` 有重复且**不重现**（+1.5 vs −2.3）——
   这是论文原有的论据；而 `horizon=2` **只有一次 run，没有重复可以反驳它**，
   我们只能照实说它是「未重复的一次测量」。
5. 加守卫：CSV 必须含 `hz2_r2`/`hz1`/`hz1_r2`，且「20s 越过的臂数」= 2。

> **不修这一条的后果**：论文用「越线不重现」反驳 20s 越线，而**能反驳的那条不是
> 头条那条**——头条那条在 20s 下越过且无重复。这是**对论文有利的漏报**。

## 二、M1：全篇判决的承重项是一条**插值**，而 Limitations 里一个字都没有

九条臂的判决 = `SLO_arm − front_slo(wall)`，而 `front_slo` 是**锚点之间的分段线性插值**。
论文在 §II 与图注里承认「这是论证不是测量」，并说它**更严**（让负结论更容易达到）——
但**没有回答「更严 ≠ 有效」**：若那条线高于静态方法真能交付的水平，
「没有臂在线上方」就推不出「没有空间」。换成最近的**已跑过**的静态点，
最近那条臂是 **+5.8pp 越过**（复核者与我复算一致）。

已补进 **Limitations**（原来只在 §II/图注）：明写这条线是插值、明写
「stricter is not the same as valid」、明写**这是本论文唯一的假设**。
加 3 条守卫（反向测试：删掉「is an assumption」→ MISS）。

## 五、复核者独立复算并确认【对】的（这一节省得下一轮重复劳动）

1. **「零条越过」对打平带与锚点集合都不敏感**：带换 ±0.5 / ±1.0 / ±2.0，
   越过数都是 **0**；锚点集合四种换法所有控制器臂的 Δ **一位不变**。
   ⇒ **问题只在线的有效性（M1），不在判决的稳定性。**
2. **「更严的是哪种」论文算对了**：线 87.98 vs 最近左锚 81.88 = +5.81pp，
   与正文的 +5.8 / +6.6 逐位相符。
3. **重复散布的事实披露完整**：六组 SLO 散布 5.11/1.0/0.5/4.4/0.8/4.9 与脚注一致。
4. **tierpair 的设计是全文最硬的一块**：同卡、背靠背（相隔 120 秒）、同池、同 trace、
   **同代码哈希**；差值 10.1 点 ≈ 同族散布的 4--20 倍。要改的是「判决怎么印」，不是设计。

## 六·补、codex r38（另一条线）—— **与子 agent 收敛在同两处**

它独立得出同一组结论（A100 的「负结果不是 24GB 卡的产物」比证据强；§III 的因果有一处外推），
另外补了三条：

1. **§III 的因果外推（与 M5 同源但更准）**：同卡配对**只有一个并发水平**
   （`tierpair.csv`：R̄ 1.508 与 1.556），所以它识别的是**该工作点上兑现率的水平**，
   不是「并发升高时它怎么变」的**斜率**。论文的窄主张（「匹配运行数与占用率时，
   host tier 保住兑现率」）站得住；**标题式的「tier 决定并发代价」则有一步外推**。
   → 已补一句 **Scope**：明写这一对是同一个在跑数上的水平比较，**斜率由 §IV 的分段 ε 给**
   （host tier 把 ε 压在 1 以下、device-only 曲线穿过 1），并明写**标题的主张靠那条曲线、
   不靠这一对**。加 2 条守卫。
2. **判据阈值的来历**：≥10 个点是**在看到新配对结果之前**定的 ✓，但定的时候已经知道
   旧配对的 12.23 点；预注册文件**没有给出为什么是 10 而不是 8 或 12 的依据**。
   → 与 M5 合并处置：正文现在印出阈值与**余量 0.14**，**不声称这个阈值有统计依据**
   （我们也不该替预注册文件补一个来历）。
3. **一个单位纠正**：我在给审查者的提问里把「0.5--7.1pp」当成了 SLO 的散布 ——

   说的是墙钟、引 0.5--5.1pp 时说的是 SLO）—— 是**我的提问**混了。记在此，免得下一轮误改正文。
