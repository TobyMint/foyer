## 对第二篇的硬约束（从这两份 review 直接抄）

1. **统计**：每配置 n≥2，报 CI 或配对 bootstrap；预注册 band/margin 并做**等价性检验**；
   不把"点估计落在带内"写成"没有改善"。
2. **基线必须实测**：静态 cap 要真的跑（且在别的 trace 上调好），不能用插值前沿代替；
   报同墙钟配对或 2D 置信域，不用 best-of-repeats 的上包络。
3. **记录 GPU clock / temp / power**：锁频或随机化运行顺序；τ 随并发升必须能排除热降频。
4. **时钟口径**：session 级 deadline 要有语义依据；engine 与 ready 双钟同权报告。
5. **不能半空转**：报预算利用率/引擎空转；否则会被判"测的是实现，不是机制"。
   ⚠ 十月线正好有这个把柄：foyer 引擎空转 56.7min vs 无控制 26.1min（DECISION_BRIEF 表），
   必须在第二篇里正面解释（驻留买复用）或者压下去。
6. **范围写进摘要**：单卡/单 trace/单 SLO 的结论不要写成一般结论。
