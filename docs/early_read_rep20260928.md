## 五、⚠⚠ 一个**必须现在就记下来**的发现：**墙钟本身会推动 Δ**

这一条比上面「墙钟长了 5%」严重得多，因为 **Δ 的定义里墙钟是自变量**：

```
delta = slo_pct − front_slo(wall_min)          （gen_table.py:221）
```

前沿是 (墙钟, SLO) 空间里的一条**分段折线**，判决用的就是「这条 run 在自己那个墙钟处、
比前沿高多少」。所以**墙钟一变，比较基准就跟着变**。

### 前沿在这一段的斜率（`frontier.py` 的 FRONT 锚点现算）

```
锚点：(207.85, 28.93)  (209.14, 68.47)  (230.31, 81.88)  (295.02, 91.59)  (527.43, 94.79)

230.31 → 295.02 段：斜率 0.1500 pp/分   ⇒ 1.0 pp 只值 6.7 分钟
295.02 → 527.43 段：斜率 0.0138 pp/分   ⇒ 1.0 pp 值 72.6 分钟
```

**判决带是 ±1.0 pp。在陡的那一段上，墙钟漂 7 分钟就顶掉一整个带宽。**


**读法**：两条新 run 的 Δ 比同修订旧 run 更负（−2.00 / −2.03 vs −1.73），
**但它们的 SLO 其实略微更好**（+0.10 / +0.20），是**墙钟把它们沿前沿推到了右边**、
比较基准抬高了 0.40–0.47 pp，才盖过了 SLO 的改善。

⚠ **注意方向**：墙钟变长 ⇒ 前沿基准抬高 ⇒ **Δ 变负 ⇒ 看起来更「在带下方」**。
也就是说**这个偏差是【对论文有利】的方向** —— 它会让臂显得比实际更靠下。
本项目记过一条纪律：**偏差方向对自己有利时更要写出来**。

### 为什么会这样：`foyer_hc_r2` 只跑了 38% 的重叠

`foyer_hc_r2` 的窗口里只有 38% 的时间有邻居，另两条是 98% / 100%。争用少 ⇒ 跑得快
（293.2 分）⇒ 基准低 ⇒ Δ 不那么多负。**两条新 run 之间的一致性其实非常好**
（−2.0012 vs −2.0330，相差 **0.032 pp**），**真正被解释掉的是旧那条**。
