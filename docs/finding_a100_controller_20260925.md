# A100 上跑控制器：**先别急着说「赢了」——基线不完整**

运行：`a100_foyer_hz2`，A100 GPU0，2026-09-25 20:03:06 → 21:36:54，
`rc=0 wall=5620.1s`，pool **983,728**（与静态扫描逐位一致），999/999 步、0 失败。

**当前结论：测量是真的，但「控制器越过前沿」目前【不能成立】，因为 A100 的静态
前沿本身没扫完。** 下面第一节是读数，第二节是那个必须补的实验，第三节是判据。

## 二、为什么现在【不能】说它赢了 —— 两个独立的问题

### 2.1 静态前沿**没扫到头**（决定性）

A100 的静态墙钟随 cap **单调下降**：cap3 136.5 → cap4 110.7 → cap5 96.4。
**扫描停在 cap5，而趋势说再往上还更快。**
于是「最快静态点 = cap5」不是前沿，只是**扫描的右端点**；
用一条被截断的曲线当包络，任何**跑到更大并发**的策略都会显得"越线"。

（历史注：2026-09-25 杀掉的那个挂了 1 天的 `a100_waiter.sh` 排的正是
`cap8/cap16`——**前人已经知道要扫得更深**，只是那批 run 从没跑成。）

**必须补**：`a100_cap6`、`a100_cap8`（与静态扫描同配置：device-only、pool 983,728）。

### 2.2 控制器的闸门**一次都没卡住**

`controller.jsonl` 2762 个采样：

    gate_full = True 的采样：0 / 2762 = 0.0%
    usage（池子利用率）：p50 = 8.7%，max = 51.9%
    active_n：p50 = 5，max = 14
    waiting_n：p50 = 0，max = 5

**闸门从未成为约束** —— 池子利用率的峰值只有 52%。所以这个控制器在 A100 上
**实质等于没有限流**（只是让它按 budget 走，而 budget 从没碰到）。
那么它比 `cap5` 快，最经济的解释是「**它没在挡路**」，而不是「它做出了更好的准入决策」。

**判据**：同车道接的 `a100_default`（完全不做准入控制）正在跑。
- 若 `a100_default` ≈ 88 分钟 → 控制器的"胜利"= 不限流的胜利，**不是准入控制的胜利**；
- 若 `a100_default` 明显更慢 → 控制器确实在做一件有用的事，那才值得往「赢」上写。

⚠ 这两个问题**互相独立**：即使 `default` 更慢，2.1 的基线截断也还在，
必须先把 cap6/cap8 补上才能谈"越过前沿"。

## 七、2026-09-25 23:1x：不控制基线跑完了 —— **但它被污染了，不能用**

`a100_default`（完全不控制）21:39→23:13 跑完，999/999、0 失败。

| | wall | SLO | R̄_busy | 占用p50 |
|---|---|---|---|---|
| `a100_foyer_hz2`（控制器） | **88.3 min** | 100.0% | 3.103 | 8.8% |
| `a100_default`（不控制）**⚠ 污染** | 88.6 min | 99.7% | 3.583 | 9.5% |
| `a100_cap5`（最快静态 cap） | 96.4 min | 100.0% | 2.336 | 8.0% |

**污染**：`gpu_watch` 365 个采样里 **82 个含 foreign**（最大 4,468 MiB），
**从 22:49:53 起** —— 另一个租户（用户 `yz`）的任务上了 GPU0。按本项目的判据，
污染会抬高逐请求 decode 间隔：

    τ₂ 中位   污染前（659 步）16.73 ms   →   污染后（209 步）**38.66 ms**（+131%）

远超 3090 那次四车道事件的 24–41%。**所以 88.6 这个数不可用**，
已重命名为 `a100_default_r2` 排队重跑（干净窗口一开就跑，
等待器 `/data/xbw/a100/a100_deep_waiter.sh` 已挂）。

### 但方向是清楚的，而且**对结论有利**

污染只会**抬高** default 的墙钟 ⇒ 真实的「不控制」只会**更接近或快于** 88.6。
所以无论干净值是多少，**控制器都不可能比不控制快多少**：
88.3 与 88.6 的 0.3 分钟（0.34%）本来就在噪声内，加上污染的方向，
「控制器 ≈ 不控制」这个读数是**保守的**。

### 这一条解释了整件事

控制器（88.3）与不控制（88.6）相当，而**两者都比最快的静态 cap 快约 8 分钟**。
再加上闸门 `gate_full` **0.0%** 卡住、池子利用率峰值 52%、峰值 14 条会话 ——

> **在 A100 上，控制器相对静态 cap 的「优势」就是【没有限流】。
> 不限流值 8 分钟，控制器在它之上再加 0.3 分钟（噪声内）。**

静态 cap 在池子不绑定的卡上是**人为限流**。这与 §III 的机制主张是同义的不同说法：
tier 决定有没有内存压力，没有压力时准入控制**无事可做**。

**注意这【不】是「控制器赢了」**：它没有比不控制做得更好，只是没有挡路。
