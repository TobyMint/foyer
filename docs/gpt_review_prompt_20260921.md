## 一、场景与设置

- 负载：泊松到达，200 个 agentic 会话，λ=0.04/s，每会话约 5 轮，共 999 步
- KV 池：101,432 token（每个 run 起服时校验，容差 ±20）

关键约束：一个会话的上下文中位数 23,187 token（占池子 22.9%），
p90 是 51,064（50.3%），最大 89,436（88.2%）。池子只能装很少几个会话。

指标定义：
- 墙钟：整个回放从起跑到最后一个会话完成
- 命中率：引擎自报的前缀缓存命中率
- SLO%：TTFT < 10s 的**步**占比（分母是成功步）
- TTFT：从"请求提交给引擎"算起，**不含**门外排队与暂停
- 并发：时间平均的活跃会话数

我的方案（代号 Foyer）：控制器按 KV token 记账决定放行哪些会话，
而不是像静态并发上限（cap-n）那样用一个死数字。三个机制：
1. 容量核算准入 + 命名许可（控制器写下确切的会话 ID 集合）
2. 状态保留式挂起（被暂停会话的 KV 下沉主机内存，SGLang HiCache）
3. 有界复活（仅设计，未实现）

**我最重要的指标是端到端墙钟，命中率/延迟是第二位。**

## 三、我昨晚做的一次实验，以及为什么它是负面的

### 触发它的观测

我给 v3 的控制器加了埋点，发现它的账本长期停在"92% of budget"，
而引擎实测只占池子的 52%。我推断：记账过于保守 → 并发上不去 → 效率差。

### 我做的改动

把内存从"优化目标"改成"红线"：

```
旧：projection = max(引擎实测占用, 各会话逻辑上下文之和) + 未来3轮增长预留
    准入条件 projection + 新会话×1.15 ≤ target_util × pool
新：committed = 引擎实测占用 + 已放行未落地 + 增长预留×gs
    准入条件 committed + 新会话 ≤ target_util × pool
```

红线和 gs（增长预留系数）是两个旋钮。跑了两个档位：
rl90 = (红线0.90, gs=0.35)，rl99 = (红线0.99, gs=0.05)

### 结果

- 记账改动**确实生效**：并发 2.12 → 2.84，引擎忙占比 75% → 81%
- **但墙钟纹丝不动**：299.3 → 300.2 分钟
- **质量掉了 7.9pp**：命中率 65.6% → 57.7%
- 激进臂更差：并发只到 3.30，墙钟 362 分钟（慢 60 分钟），被 cap3 完全支配

### 我给出的机制解释

并发上去 → 工作集超过池子 → 引擎驱逐 → 重算 → 单会话变慢。
具体数字：rl90 并发 +0.72，但单会话执行时间从 2.2 分涨到 2.9 分（+32%），
占用总量（并发×墙钟）从 634 涨到 852 会话·分钟（+34%），正好抵消。

激进臂被自己的安全机制反噬：它有一个"硬阀"（实测占用超过阈值就停止准入
并挂起会话），阈值设在了 0.98 而它的工作点就在 0.93 附近，
结果 2162 次决策里触发 971 次（45%），引擎有 28% 的时间空转（cap3 只有 13%）。

### 账本分解，解释"平台区"的成因

```
                   rl90(gs=0.35)      rl99(gs=0.05)
红线                91,287             100,418
引擎实测 中位       72,690 (80%)       70,189 (70%)
增长预留 中位       13,492 (15%)        1,883 ( 2%)
committed 中位      91,089 (100%)      80,003 (80%)
```

rl90 的增长预留正好吃掉了再放一个会话所需的余量
（80% + 15% = 95%，再加新会话 20% → 115% > 100%）。

## 四、一个我必须先交代的算术

每会话约占池子 23.6K token（实测），新会话到达需约 20K。
所以四个并发会话需要约 117K，**超过 101,432 的池子**。

也就是说：要跑在并发 3.5–4（= cap3/cap4 的位置，墙钟 258 分），
**必须故意超订池子**，让引擎自己驱逐腾地方。
而 cap3/cap4 的命中率只有 49.8%/45.9%——超订的代价就记在这里。

这就是我的两难：
- 不超订 → 并发上不去（≤3）→ 墙钟 ~300 分，打不过 cap3/cap4
- 超订   → 墙钟可能到 258，但命中率会掉到 50% 左右（cap3/cap4 的水平）
