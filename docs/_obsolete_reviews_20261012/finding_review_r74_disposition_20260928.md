## 一、两条线合起来，真正的发现是 **1 个**（其余是它的两个侧面）

### ★ 主发现：**块切分里那份「用正则近似词法」的代码，我上一轮没修**

中立复核 §7 给了**可复现构造**：`check_paper_numbers.py` 的绝对路径守卫在切
「逻辑行（括号块）」时，逐物理行挖空用的是
`re.sub(r'"[^"]*"|\'[^\']*\'', …)` —— 于是

```
BASE = "/root/paper/foyer/paper/data"
HELP = """
  run.sh --foo (
  run.sh --bar
"""
p = BASE + "/x.csv"
open(p, "w")
```

**不报**（把一个 `(` 删掉就报）。根因链：三引号里那个孤立的 `(` 把深度计数带偏 ⇒
后面几行被并进一个**从字符串中间开始**的块 ⇒ 该块不是合法 Python ⇒
`_names()` 里的 `tokenize` 抛错 ⇒ **返回空集** ⇒ 闭包支对该块完全失明。

⚠ **这是我第三次在同一个坑上出错，而且这次最难看**：r72 是跨字符串的 `)`，
r73 是三引号 + 回溯 —— 我修了 `_blank`，**却没看旁边三行的同一份正则**。

**处置（三处）**：

1. **块切分改用词法器**：整文件 `_blank()` 挖一次（跨行字符串才挖得对），
   再按**行号**取回每一行。用 `split("\n")` 而不是 `splitlines()` ——
   要与 `_blank` 的行计数对齐（`splitlines` 还会在 `\f`/`\x85` 处断行）。
2. **`_toks()` 失败返回 `None`，不再返回 `[]`** —— 原来「词法化失败」与
   「这段没有名字」**不可区分**，三个调用点全都会把这个空集当成事实，
   方向**一律是漏报**。现在三个调用点各自往**有界的安全侧**回落。
3. **`_blank()` 失败也显式化**（返回 `(文本, ok)`）：见下面第二点。

### 第二点：`_blank` 的回落方向 —— **我上一轮的注释把方向写反了**

我在 r73 的注释里写「`tokenize` 抛错时原样返回 = 保守：宁可多报也不漏报」。
中立复核 §5④ 给了**两个反向构造**，证明回落是**双向**的：

- **漏报**：`x = ('未闭合` ⏎ `open(D, ")", "w"))` ⇒ `_is_write` 返回 **False**
  （真写被漏；未挖空时字符串里的 `)` 提前把配平打到 0，逗号扫描跑偏）；
- **误报**：字符串里装着假写调用 ⇒ **True**。

**漏报那一支正是这条审计最怕的方向**（沙箱挡不住 ⇒ 会写回活树）。

⚠ **codex 这一条判反了**：它 §5 只测了误报那一支，就下结论「这是该守卫较保守的方向」。
**中立复核给出的漏报构造它没有**。这是本轮两条线唯一的实质分歧，而**中立那条是对的**。

**处置**：`_blank` 改为返回 `(文本, 是否挖空成功)`；`_open_has_mode` 在失败时
**按「算不出来」处理并报**（假报只是噪声、看得见；漏报会静默毁掉活树）。

⚠⚠ **这里我自己差点造出更大的错**：第一版把 `_pathy()` 的失败回落也写成
`return True`，活树上立刻多出 **4 条假报**（`agg.py` / `decode_rate.py` /
两个 `smoke_*.py`）。原因：`_asg` 只取**一行**，所以**任何跨行语句**
（`ctrl = subprocess.Popen(`）都会词法化失败 —— 那是**常态**，不能一律当 True。
⇒ 两处回落改成**有界的文本判据**（`join(` / `os.sep` / `pathlib` / 引号串里含 `/`；
闭包增长用词边界匹配）。改完活树回到 0 MISS。

## 三、三处「不处置 / 只记录」的理由

1. **标签守卫不补内容对拍**。要查「标签内容是否正确」，检查器就得复现
   `make_figs.py` 的挑选逻辑（`DECOMP_KEEP` + 排序）—— 那就是本项目栽过的
   **「同一件事两份实现」**（CLAUDE.md：codex 第 21 轮四条同形状）。
   而**标签↔柱子的对应是构造保证的**（`_ylabs` 与 `ax.set_yticklabels(_ylabs)`
   是同一个列表），图注又**不枚举**名字、没有第三方可对。剩下的风险面由**条数守卫**兜着
   （图注的 "seventeen" / "One bar is hatched" 都对着 `.counts.json` 现算的数）。
   ⇒ 已在代码注释里**明示作用域**：抓得住重名事故，抓不住「唯一但错误」。

2. **`regen_all.sh` 不管 `paper/figs/`**。它只重建并对拍 `paper/data/*.csv`；
   图与两个 JSON 由 `make_figs.py` 产出，而 `make_figs.py` **需要 matplotlib**，
   不在 AE 的「仅 stdlib」复现路径上（这正是本批要保住的性质）。
   ⇒ 不在 `regen_all.sh` 里加绘图步骤；**改由检查器兜**：新增的卫兵要求
   **两个 JSON 都不比 `paper/figs/` 下任何一张 PDF 旧**。

3. **brief 的两处文件名是我写错的**（图 7 计数在 `.counts.json` 不在 `.labels.json`；
   `.labels.json` 不在 `regen_all.sh` 里）。两条线都按**实情**核的，没有按我的措辞核 ——
   这是对的做法。已在本文件更正。

**代价口径**：codex §10 的 51.7 vs 10.2 ms 是**整文件**计时，而检查器实际传的是
**逻辑行片段**；中立复核在检查器内插桩实测：`_blank` 调 6806 次、累计 **0.279 s**，
整轮 3.44 s ⇒ **约 8%**。换取的是病态输入 1.25 s → 0.0001 s。
