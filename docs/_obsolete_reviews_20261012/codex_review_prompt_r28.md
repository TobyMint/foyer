## 一、半池实验（今天并入 §I 与 §III）

**做了什么**：把池子减半（101,432 → 50,716），同一张卡、同一条 trace、同一份代码，
**只动池子**。三条 run 的结局：

    cap2_hp  999/999 步、0 失败      -> 唯一有效的兑现率读数
    cap3_hp  807/999 步、50 失败     -> 引擎 OOM 崩了
    cap4_hp  549/999 步、116 失败    -> 引擎 OOM 崩了

**怎么写的**（`paper/sec_model.tex` 的「capacity-controlled version」那一段，
以及 `sec_intro.tex` 两处）：

1. 净效应 **−4.6 pp**：半池 cap2_hp 的兑现 87.1%，而**在全池那条「兑现 ~ R̄」曲线上
   取同一个 R̄（1.08）插值**得 91.7%。差值 −4.6。
   —— 因为半池的 R̄ 自己也降了（1.08 vs 全池 cap2 的 1.27），**不能直接比 87.1 与 89.7**。
2. 崩掉的两条**不产生兑现率**（删失样本），只写成「可行性边界」：
   「at caps of three and four the engine exhausts the pool … and faults,
   and both runs stop short of the replay (807 and 549 of 999 steps, 50 and 116 failed requests)」

**请核**：

- A1. −4.6 pp 这个比法对不对？「在全池曲线上插值」是不是合法的对照？有没有更好的口径？
- A2. 把「引擎 OOM」当成**科学观测**写进论文，强度是否过头？它会不会其实是**我们的配置问题**
  （memfrac 0.73 的下界、SGLang 版本、cap-file 机制）而不是「池子大小」的效应？
  **证据**：全部 ~165 条 run 的 server 日志里带 `Out of memory` 的**只有半池那两条**；
  全池跑过 concurrency 94.9（`default`）与 7.63（`cap8_hc`）都没 OOM。
- A3. 半池 50,716 **小于** trace 最长的单请求 66,571。正文有没有把这个混淆说清楚？
  （实测：那三条超池请求**被成功服务**了，崩在几十步之后的小请求上 —— 所以不是它们触发的。）
- A4. 崩掉的 run 也写了 `summary.json`、`runner_rc` 还是 **0**（`stop_session_on_error`
  让所有会话到终态、runner 就正常退出）。正文有没有**暗示它们跑完了**？

## 二、A100 上第一次跑控制器（今天新增的 §A100 段落）

**读数**（干净，`gpu_watch` 363 采样 0 foreign）：

    a100_foyer_hz2（控制器）  88.3 min  SLO 100.0%  999/999  闸门 gate_full 0.0% 卡住、池子利用率峰值 52%、峰值 14 条会话
    a100_cap5（最快静态点）   96.4 min  SLO 100.0%
    a100_default（不控制）    88.6 min  SLO  99.7%   ← **被污染，不进任何数据表**

**正文写的**：我们**不**把控制器的 88.3 读成赢，两条理由 ——
(1) 静态扫描停在 cap5 而墙钟随 cap 单调下降（136.5 → 110.7 → 96.4），
所以「最快静态点」是**扫描的端点**不是前沿；(2) 控制器的闸门一次都没卡住。
并写明「正补更大 cap 的静态点、并重跑被共租污染的不控制基线」。

**请核**：

- B1. 这两条理由是否**足以**支撑「不读成赢」？有没有漏掉的第三条解释？
- B2. 有没有把**还没跑完**的（`a100_cap8` / `a100_cap16` / `a100_default_r2`）
  写成已跑或已得结论？本项目栽过两次这个坑。
- B3. 同一个读数在**四个地方**说过（§A100 两段、§Discussion 的 Limitations、
  §I 的「What we do not claim」）。**逐处比对口径是否一致**，有没有一处比另一处强。
- B4. `a100_default` 被污染这件事（τ₂ 中位 16.73 → 38.66 ms，最后 24 分钟与别人同卡），
  正文的处置（「first measurement co-tenancy made unusable」）够不够？
