## 一、弱点一：「预期 >=85%」没绑定到任何一个 cap

五个 3090 值跨 92.5% ~ 36.4%，「同一批 cap 都 ≥85%」与「cap1 保持 ≥85%」是强度完全
不同的两个检验，而原文没定下是哪个。**补：判据分档，逐 cap 比。**

3090 device-only 的对照点（`paper/data/reuse.csv`，与 `gen_a100.py` 同口径）：

| cap | R̄_busy | 兑现率 |
|---|---|---|
| cap1 | 0.998 | 92.5% |
| cap2 | 1.271 | 89.7% |
| cap3 | 1.534 | 79.0% |
| cap4 | 1.650 | 60.7% |
| cap5 | 1.841 | 36.4% |

**cap1 与 cap2 在 3090 上本来就 ≥85%，它们不能区分任何假设** —— 原文把它们列进判据
是重复计数。**能区分的是 cap3/cap4/cap5。**

判据（看结果前定死）：

- **支持「塌点由容量定」**：A100 在 cap3 **和** cap4 上都兑现 ≥85%，
  且 cap5 兑现 ≥ 65%（即 3090 的 36.4% 至少翻近一倍、并越过 50% 线）。
- **证伪**：A100 在 cap4 上的兑现落在 3090 的 60.7% ±10 点以内（≤70.7%），
  或者 cap5 落在 36.4% ±10 点以内（≤46.4%）。即「在同样的 cap 上塌到同样的水平」。
- **两者之间**：部分支持，**照实写成部分支持**，不向上取整成支持、也不向下取整成证伪。

## 二、弱点二：「塌点被推到更高的 R̄」没有操作阈值

**补：把「塌点」定义成一个可算的量 —— 兑现率穿过 50% 时的 R̄。**

3090 上它落在 `cap4`(R̄ 1.6505, 60.7%) 与 `cap5`(R̄ 1.8409, 36.4%) 之间，
两点线性插值得 **≈ R̄ 1.734**。这是 3090 的塌点读数，**在 A100 数据回来之前算好的**。

- **支持**：A100 的 50% 交叉点 **> 1.734**（即它穿过 50% 时已经在更高的 R̄ 上）。
- **证伪**：A100 的交叉点 **≤ 1.734**。
- ⚠ **「没穿过 50%」不能直接判成支持**（codex 第 22 轮指出）：它有两种截然不同的成因 ——
  兑现率**一直高于** 50%（那就是支持），或者**一直低于** 50%（那是更彻底的塌陷，是证伪）。
  所以这条要先看**端点的兑现率**：cap5（我们跑到的最高 R̄）若 ≥ 65% 才算「没穿过」的支持，
  若 < 50% 则按证伪处理，两者之间按部分支持写。

## 四、两条口径的前提（写下来免得事后争）

1. **比的是同一个 cap，不是同一个 R̄。** 卡快了以后同一个 cap 的 R̄ 会不一样。
   表里两个都给，如果 R̄ 差得远，结论要写明「同 cap、R̄ 差 x」。
2. **`R̄_busy` 与兑现率都走共用定义**（`gen_decomp.busy_stats` / `gen_reuse.trace_ceiling`），
   A100 与 3090 各算各的会分叉 —— 已改（见 `docs/finding_review_r21_disposition_20260925.md` 第四节）。
3. **`gpu_watch` 全程在记**；若 `n_foreign != 0` 出现，那一段的 τ 与 SLO 不可用，
   但**兑现率是体积量**，与时间无关，仍可用（与 3090 侧同一处理）。

## 五、这一页的自我限定

判据是我在**看过 3090 的数、没看过任何 A100 的数**的情况下写的。codex 第 22 轮把这一点
问得很准，照实答：

- 「**预期 ≥85%**」不是这一页新造的 —— 它已经在 02:52 的 `a100_toolchain_20260925.md`
  与 02:47:29 的 `lane_a100_dev.sh` 里，**在 A100 起跑之前**。
- 「**逐 cap 的规则**」「**±10 点**」「**50% 交叉**」这三条是**这一页才操作化的**，
  而且**是看着 3090 的那五个数写的**（±10 点直接围绕 60.7% 与 36.4% 划，
  1.734 直接由 3090 的两点插值而来）。

所以它们的地位要说清楚：**它们是「对 A100 而言的事前判据」，不是「对 3090 而言的事前判据」。**
用 3090 的数去定一条关于 A100 的规则，如果 A100 的机制与 3090 相同，这条规则就是
自我实现的；它真正的用途是**在两种结果之间给出一个事先约定的分界**，
避免事后挑一个好看的口径。这个用途它胜任；把它读成「独立验证」则过头。

三条阈值都是判断，不是从数据推出来的，但**对两种结果都留了出口**。
原判据的最后一句仍然有效：

> 若 A100 在同样 R̄ 上塌到同样水平，「容量定塌点」被证伪。两种结果都照实写。
