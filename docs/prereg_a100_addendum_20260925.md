## 一、唯一的判决轴：兑现率穿过 50% 时的 R̄

**先说清楚为什么只有一条轴。** 这一页的初版写了**两套**规则（逐 cap 的 ≥85%/±10 点，
与 50% 交叉），中立子 agent 第 9 轮给出了一个两套结论相反的算例：A100 取
cap4=75%@R̄1.8、cap5=40%@R̄2.5 时，逐 cap 规则判**证伪**（40 ≤ 46.4），
50% 交叉判**支持**（交叉点 2.3 > 1.734）。两套规则同时成立、判决相反 —— 那等于没有判据。
**所以只留一条，并以它为准。**

**留 50% 交叉这一条**，理由有二：
1. 它与原始预注册**同轴**。`lane_a100_dev.sh:12-13` 与 `a100_toolchain_20260925.md:51-52`
   写的是「同一批 cap 在**同一 R̄** 上」「若 A100 仍在**同样的 R̄** 上塌到同样水平……被证伪」——
   都是 R̄ 轴。逐 cap 规则换成了 cap 轴、且不加任何 R̄ 条件，那是另一回事。
2. 它不随卡的速度漂移。同一个 cap 在 A100 上的 R̄ 与 3090 不同，逐 cap 比就是拿
   两个不同的工作点在比 —— 正是 §VII 刚撤回的那类错。

**定义**：把 A100 的兑现率对 R̄ 作分段线性曲线，取**兑现率 = 50%** 处的 R̄。
3090 的同一条曲线取在 `cap4`(R̄ 1.650488, 60.7432%) 与 `cap5`(R̄ 1.840948, 36.3560%)
之间，插值得 **R̄ = 1.7344**（用印出的两位小数算是 1.7343）。这个数**在 A100 数据回来之前算好**。

**判决**：

| A100 的 50% 交叉点 | 判决 |
|---|---|
| > 1.7344 | **支持**「塌点由容量定」 |
| ≤ 1.7344 | **证伪** |
| 在 R̄ ≤ 1.7344 的范围内**一次也没到过 50% 以下** | **支持**，但必须同时满足 **max R̄ ≥ 1.7344** |

最后一行那个附加条件是中立子 agent 第 9 轮补的，**必须加**：R̄ 随卡变，如果 A100 的
cap2~cap5 全落在 R̄ < 1.7344 的区间里，「没穿过」是**因为没测到那儿**，不是因为塌点上移。
不满足 `max R̄ ≥ 1.7344` 时，结论只能写成
「在 R̄ ≤ X 的范围内未观察到塌点」，**X 是多少就写多少**。

## 二、逐 cap 的数：描述性，不作判决

**这一节不作判决**（理由见上）。它只把两边的读数并排，供读者自己看，也供我们把
「同 cap、R̄ 差多少」写进正文。

3090 device-only 的对照点（`paper/data/reuse.csv`，与 `gen_a100.py` 同口径）：

| cap | R̄_busy | 兑现率 |
|---|---|---|
| cap1 | 0.998 | 92.5% |
| cap2 | 1.271 | 89.7% |
| cap3 | 1.534 | 79.0% |
| cap4 | 1.650 | 60.7% |
| cap5 | 1.841 | 36.4% |

**cap1 与 cap2 在 3090 上本来就 ≥85%，它们不能区分任何假设。** 这一句初版写了，
但它**只在拿 3090 当参照时才成立** —— 所以初版第五节说「这三个阈值不是从数据推出来的」
是**不准确的**，见下节。

### 关于初版那三个阈值的来历（逐条回答，中立子 agent 第 9 轮要求）

- **±10 点：撤回。** 锚在 3090 的值上是对的（零假设要有参照），但**宽度没有依据**：
  仓库里兑现率的重复对散布 ≤ 0.25 点（`reuse.csv` 的 cap3_hc/cap3_hc_r2 差 0.18 点、
  cap4_hc/cap4_hc_r2 差 0.24 点），±10 点是它的约 40 倍。后果很实在：A100 在 cap4 上
  比 3090 **好 9 个点**也会被判成「塌到同样水平」。既然判决轴已经换成 50% 交叉，
  **这条宽度整个去掉**，不再出现在任何判决里。
- **≥85%：保留为描述性参照，不作判决。** 它确实早于 A100 起跑（在 02:52 的 toolchain
  文档与 02:47:29 的部署脚本里），方向也对我们不利；但它落在 3090 的缝里
  （cap3 的 79.0 < 85 < cap2 的 89.7），本身不能区分假设。
- **cap5 ≥ 65%：撤回。** 初版给的理由是「至少翻近一倍、并越过 50% 线」，
  而 36.4 翻倍是 72.8、越过 50% 线是 50 —— **两条都推不出 65**，这个数不可复算。
  判决轴换成 50% 交叉之后不需要它了。

## 四、两条口径的前提（写下来免得事后争）

1. **比的是同一个 cap，不是同一个 R̄。** 卡快了以后同一个 cap 的 R̄ 会不一样。
   表里两个都给，如果 R̄ 差得远，结论要写明「同 cap、R̄ 差 x」。
2. **`R̄_busy` 与兑现率都走共用定义**（`gen_decomp.busy_stats` / `gen_reuse.trace_ceiling`），
   A100 与 3090 各算各的会分叉 —— 已改（见 `docs/finding_review_r21_disposition_20260925.md` 第四节）。
3. **`gpu_watch` 全程在记**；若 `n_foreign != 0` 出现，那一段的 τ 与 SLO 不可用。
   兑现率怎么处理，**按论文的口径写、不按这一页的方便写**：论文对同一件事的措辞是
   「suggestive, but not proof, since co-tenancy could in principle also reorder
   completions and change eviction order」（`sec_discussion.tex`），
   而且只有**一条臂**的对照（`superseded.csv`），论文自己说
   「one arm is one comparison, and we are not claiming more than that」。
   所以：出现外部进程时，兑现率**也只能作为提示**，判决要降级并写明。
   （初版这一条写成「体积量与时间无关，仍可用」，比论文强，已改。）
   附带一条数据事实：对照表里的 cap1 在 `reuse.csv` 里是 **CONTESTED**，用它当参照
   本来就要带这个限定。

## 五、这一页的自我限定

codex 第 22 轮与中立子 agent 第 9 轮把「这些阈值是哪来的」问得很准，照实答：

- 「**预期 ≥85%**」不是这一页新造的 —— 它已经在 02:52 的 `a100_toolchain_20260925.md`
  与 02:47:29 的 `lane_a100_dev.sh` 里，**在 A100 起跑之前**。现在它只是描述性参照。
- 「**50% 交叉点 = 1.7344**」是这一页**看着 3090 的两个数算出来的**
  （cap4 的 60.7432%@R̄1.650488 与 cap5 的 36.3560%@R̄1.840948 之间插值）。
- 初版的「±10 点」与「cap5 ≥ 65%」**都已撤回**（前者宽度无依据，后者的数不可复算）。

所以判决轴的地位要说清楚：**它是「对 A100 而言的事前判据」，不是「对 3090 而言的事前判据」。**
用 3090 的数去定一条关于 A100 的规则，如果 A100 的机制与 3090 相同，这条规则就是
自我实现的；它真正的用途是**在两种结果之间给出一个事先约定的分界**，
避免事后挑一个好看的口径。这个用途它胜任；把它读成「独立验证」则过头。

原判据的最后一句仍然有效：

> 若 A100 在同样 R̄ 上塌到同样水平，「容量定塌点」被证伪。两种结果都照实写。
