# 学术写作

## 先做的事（不要跳过）

1. **确定在改哪一节**。看 `paper/main.tex` 的 `\input{}` 顺序，读目标 `sec_*.tex`，
   以及它前后各一节——论证是连着的，单看一节会写出接不上的过渡。
2. **读证据**。`paper/claims_audit.md` 是写正文前的闸门：每条主张要过四关
   （实测数字 / 有对照 / 自己试过推翻没有 / 可复现路径）。**没进这张表的主张不要写进正文。**
   数字从 `paper/data/*.csv` 取，不要从记忆或旧稿里抄。
3. **看撤回记录**。`CLAUDE.md` 的「撤回记录」一节列了不许复活的主张。

## 论证结构

按 **claim → evidence → interpretation** 排：

- 一句能站住的主张，
- 支撑它的实测数字（带对照），
- 然后才是这意味着什么。

不要反过来先讲意义再补数字。审稿人先看数字。

## 这个项目的写作习惯

- **主动写自我限制**。步时间是两个导出量互证而非引擎直采、25 档对照跨代、
  哪条 run 被打断没跑完——这些要在正文里自己讲，不要等审稿人抓。
- **报告分布不报单点**。中位/均值/p90/最大一起给（见 `CLAUDE.md` 教训 2）。
- **负结果照实写**。九条变体无一越线就是无一越线，不要用 "comparable to" 之类的话
  把落后说成持平。判决由 `scripts/lab/frontier.py` 机械产出，不要用文字绕过它。
- **区分「测出来的」和「推出来的」**。前者写 "we measure"，后者必须带推导过程或标注为推论。
  机制解释被推翻过一次（见撤回记录），凡是解释都要留余地。

## 不要做的

- 不加新主张、新引用、新数字、新结论。
- 不写 "novel" / "significant" / "state-of-the-art" 这类没有证据支撑的形容词。
- 不用 "delve" / "it is worth noting" / "in conclusion" 这类填充语。
- **改了措辞还是改了结论，要明说**。只动措辞就直接给；动了科学含义要先讲清楚动了什么、
  为什么，让用户决定。

## 证据不够时

标出来，不要补。用 `[证据缺口: <缺什么>]` 就地标注，然后继续写别的部分。
